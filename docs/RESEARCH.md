# pi-goal Research Brief: Raising Final-Output Quality

## 1. Executive Summary

- **The single biggest leverage point is moving quality enforcement off the end-gate and into the loop.** Today pi-goal checks completion once, at `agent_end`, via a self-reported evidence schema. Every strong system surveyed (PRM course-correction `arXiv:2509.02360`, LLMLOOP `arXiv:2603.23613`, Claude Code PostToolUse, Cursor preToolUse) applies pressure *continuously* — after each edit and every K steps — so drift and broken builds are caught in the same turn they occur, not after 30 wasted turns. pi-goal already owns the `tool_call`/`tool_result` hooks needed to do this; they are currently unused for steering.

- **Self-reported evidence should become environment-verified evidence.** The `goal_complete` schema (requirementsCovered, verificationsRun, taskEvidence, shortcutsConsidered) is a well-designed *narration* prompt, but nothing checks it against reality. The SWE-bench fail-to-pass oracle and Factory's validation-contract pattern both make completion *binary and machine-checked*: tests that were red at goal-set must be green, lint/typecheck must exit 0, before `goal_complete` is accepted. pi-goal has `pi.exec` to run exactly these checks inside the gate.

- **A separate, cheaper judge model should grade completion — the agent must not certify its own work.** Claude Code's `/goal` Haiku evaluator, SWE-RM, and G-Eval all separate the doer from the auditor. "Gaming the Judge" (`arXiv:2601.14691`) shows self-assessment is unreliable. pi-goal can spawn a read-only verifier session (fork/spawn API) that classifies each requirement CONFIRMED / PLAUSIBLE / REFUTED against actual files and test output, and only CONFIRMED clears the gate.

- **Scope enforcement is the cheapest high-impact win and is currently absent.** The most common coding-agent failure is solving adjacent problems. Spec-Driven Development and Codex's six-component goal schema both demand an explicit *out-of-scope* list. pi-goal can collect it at goal-set time, inject it every turn, and hard-block writes to out-of-scope paths via the `tool_call` hook — a small change with large drift-reduction.

- **Upfront Plan-and-Solve decomposition beats emergent task discovery.** Tasks currently emerge implicitly. Forcing one read-only planning turn (Plan-and-Solve `+8pp`, Codex plan mode, Claude plan mode) that commits a task list before any edit surfaces ambiguity and gives the gate a real checklist. pi-goal can gate this with a planning-phase flag in the injected `<goal_state>`.

- **Failure should compound into learning, both within and across sessions.** Reflexion (91% vs 68% on HumanEval) writes a post-mortem on each failed attempt and re-injects it; Cursor's continual-learning plugin and Trace2Skill distill session traces into AGENTS.md/skills. pi-goal already persists everything in SQLite and can contribute skills via `resources_discover` — the substrate for a gradient-free ratchet is already there.

- **Periodic escalation tiers turn the loop into a controller, not just a blocker.** Cursor's `loop_count` and pi's existing `setThinkingLevel`/`setModel` let early passes run cheaply and later passes escalate thinking/model — spending compute only when the agent is struggling.

- **Watch token cost and judge-gaming.** Every in-loop check, judge call, and re-injection costs tokens and latency. The research is explicit that PRM gains cost real money (`$23/extra success`), oversized always-on context *reduces* adherence, and chain-of-thought judges are gameable. Default everything to a cheap model, keep injected context slim, and make heavy checks opt-in or cadence-gated.

## 2. Per-Area Distilled Findings (deduped)

**Loop architecture (Stream 1).** ReAct is the right backbone (already in use). The enrichments that matter: Reflexion failure-memory, Self-Refine generate→critique→refine, Plan-and-Solve upfront decomposition, and a PRM-style *periodic* monitor using the Specification/Reasoning/Coordination error taxonomy every 5 steps. Completion gating should layer: deterministic DAG checks (tests ran? passed?) → subjective rubric score → hard circuit breakers (max turns, no-progress detection).

**Factory.ai Missions (Stream 2).** The standout is the **pre-authored validation contract**: numbered behavioral assertions with evidence requirements written *before* implementation, tracked in a state file, all of which must be `passed` before completion. Plus: orchestrator/worker context isolation, auditable typed dismissals for skipped work (≥20-char justification), TDD red-green as the only exit condition, and dual milestone validators (scrutiny + black-box).

**Codex / AGENTS.md (Stream 3).** The six-component goal schema (outcome, verification surface, constraints, boundaries, iteration policy, **blocked-stop condition**) is a direct upgrade to pi's goal-set input — the blocked-stop condition closes the "I tried my best" escape. AGENTS.md `## Review guidelines` as a *mechanical* (not qualitative) pre-completion checklist. Codex-1's RL-on-test-pass prior means surfacing exact test commands early aligns the model's trained behavior with the gate. Plan mode as a modal read-only phase. Explorer/worker/orchestrator role split.

**Claude Code persistence (Stream 4).** TaskCreate lifecycle invariants worth copying: exactly one task `in_progress`; never mark complete with failing tests; `blockedBy` dependency edges. The Stop-hook + `stop_hook_active` loop guard maps onto pi's `agent_end` continuation (pi needs an equivalent guard against infinite gating). Haiku condition-evaluator with evidence-quoting. PostToolUse inline test/lint injection. Worker Fork verifier with CONFIRMED/PLAUSIBLE/REFUTED.

**Cursor self-improvement (Stream 5).** The continual-learning stop-hook (cadence-gated, transcript-delta, appends bullets to AGENTS.md) — *this repo already has `.cursor/hooks/state/continual-learning.json` installed*. preToolUse tool-boundary steering. Bugbot learned-rules from structured signals (pi's evidence fields are an untapped signal source). Orchestrate planner/worker/verifier fan-out. `loop_count` escalation tiers.

**Environment as steering (Stream 6).** SWE-bench fail-to-pass oracle. LLMLOOP's five-stage loop (compile → lint → test → mutation → coverage). SWE-RM execution-free judge as a supplement when tests are weak/absent. Spec-driven out-of-scope blocking. Trace2Skill / MUSE-Autoskill skill lifecycle with unit-test-gated skill admission.

## 4. Open Questions / Risks

- **Does pi's `tool_result`/`context` hook actually forward injected text into the *model's* context under every provider?** `index.ts` documents that cursor-agent strips synthetic user-message bodies and that custom-role context messages are the only reliable channel. The known copilot-cli bug (`#2980`, S6) is that `additionalContext` is sometimes captured but not forwarded. **Before building #2/#5/#15, verify empirically that text injected via `tool_result`/`context` reaches the LLM across the providers pi supports.**

- **Where do validation commands come from?** #1/#2/#16 assume discoverable test/lint/typecheck commands. Heterogeneous repos (no test runner, monorepos, non-JS stacks) break this. Need a `pi-goal` config file or AGENTS.md convention, plus graceful degradation to a judge model (#7/SWE-RM) when no oracle exists. ~31% of SWE-bench suites are weak enough to pass wrong patches (`arXiv:2506.10954`) — exec-gating is necessary but not sufficient.

- **Token and latency budget.** In-loop monitors (#5), per-edit lint (#2), and judge calls (#4/#7) multiply cost; the PRM paper's `$23/extra success` is the warning. Need cadence gating, cheap default models, and a kill switch. Quantify added tokens/turn against the existing `eval/ideation-workflow.js` harness before shipping always-on checks.

- **Judge-gaming and infinite loops.** Self-judging is unreliable (`arXiv:2601.14691`); a separate verifier (#4) mitigates it but a verifier sharing the same base model may collude. pi's `agent_end` continuation has **no `stop_hook_active`-equivalent guard today** — adding more block paths (#1, #4, #12) risks infinite gating. #11's hard-stop counter is a prerequisite, not optional.

- **Plan-mode rigidity vs. discovery.** Gating task creation after a planning phase (#6) prevents scope creep but also prevents legitimate mid-execution discovery. Need an escape hatch (re-open planning with justification) so the gate doesn't trap the agent when the upfront plan was wrong.

- **Where do new structured inputs live?** Out-of-scope (#3), validation contract (#12), six-component schema (#9) all need SQLite schema changes. `goalManager.ts` uses `DELETE FROM goal_tasks` on every save and INSERT…ON CONFLICT — adding tables/columns needs a migration strategy and care that rehydration (`adoptPersistedGoal`) stays correct.

- **Fork/spawn semantics are assumed, not verified.** #4, #14, #17, #18, #20 lean on fork/spawn/navigateTree. AGENTS.md lists these as available to *command handlers* — confirm they are callable from `agent_end`/tool-execute contexts, whether forked sessions inherit the goal extension, and how results return to the parent before designing the verifier/orchestrator workflows.

- **AGENTS.md auto-edit safety (#14/#18).** Research shows LLM-generated AGENTS.md content *reduces* success and raises cost >20% (S3, asdlc.io). Any auto-append needs the propose-then-approve gate (Cursor Memories) and strict WHAT/WHERE/EVIDENCE structure with a hard size cap, or it degrades the very baseline it aims to raise.
